# حفظ الإرث — واجهة تجربة وثائقية تفاعلية

Next.js (App Router) experience for the documentary site about **حسن نصر الله**,
built to the second style of the visual identity guide («الأسلوب الثاني: المرئيات والزخارف»).
Arabic, RTL, blue ground, gold as a point of light, ornament grid, GSAP + ScrollTrigger.

Content is managed in **Payload CMS 3**, which runs inside the same Next app: the admin panel is at
`/admin`, the REST API at `/api`, and the data lives in Postgres. The AI assistant is still a UI mock.

## Run locally

Requires Node 20.9+ and Docker (for the development database).

```bash
npm install
cp .env.example .env        # then set PAYLOAD_SECRET to a long random string
docker compose up -d        # Postgres on localhost:5434
npm run seed                # loads the client-provided content (safe to re-run)
npm run dev
```

Open http://localhost:3000, and http://localhost:3000/admin to create the first account — the first
account is always an admin. In development the database schema follows the code automatically.

| Script | What it does |
| --- | --- |
| `npm run dev` / `build` / `start` | Next.js |
| `npm run lint` · `npm run typecheck` | ESLint · TypeScript |
| `npm run seed` | fills only what is missing; never overwrites what editors changed |
| `npm run migrate:create -- <name>` | after changing a collection or field, records a migration |
| `npm run migrate` | applies pending migrations (production) |
| `npm run generate:types` | regenerates `src/payload-types.ts` after schema changes |
| `npm run generate:importmap` | regenerates the admin import map after adding admin components |

Deploying to the server: see [DEPLOYMENT.md](DEPLOYMENT.md).

## Stack

Next.js 16 (App Router, TypeScript), React 19, Tailwind CSS v4, GSAP 3.15 (ScrollTrigger, SplitText) via
`@gsap/react`, Payload CMS 3 with Postgres and the Lexical rich-text editor.

## CMS

```
src/payload.config.ts        the CMS: collections, globals, database, uploads, Arabic admin
src/payload/collections/     one file per content type
src/payload/globals/         single documents: site settings, person, من نحن, home selections, page intros
src/payload/fields/          shared fields — the video field, slug, stage, year
src/payload/hooks/           cache invalidation on publish
src/payload/seed/            the content that existed before the CMS
src/migrations/              database migrations (generated)
src/lib/content/             the site's read side: cached queries, CMS → site mappers, types, search
src/lib/actions/             server actions: site search, the two public forms
src/app/(frontend)/          the site
src/app/(payload)/           the admin panel and API (generated by Payload — do not edit)
```

**What editors manage.** Biography stages (drag to reorder), milestones, the archive (photos, videos,
texts), speeches, «عين» articles (rich text), «دار النشر» books, the gallery, hero slides, the homepage
selections, «من نحن», the person, page intros, contact details and social links. Every content collection
has drafts: nothing is public until it is published.

**Video.** Every place that plays a video uses one field (`src/payload/fields/video.ts`): either a link
(YouTube, Vimeo, Facebook or a direct MP4/WebM URL — validated on save by `src/lib/video.ts`) or a file
uploaded to the «ملفات الفيديو» library. `<VideoPlayer />` shows the poster and plays in place, in the
provider's player or in a native `<video>`. YouTube links bring their own poster.

**Uploads** are written under `UPLOADS_DIR` (`uploads/` locally): `media/` images, `videos/`,
`documents/`, and `private/submissions/` for files visitors send, which only staff can open. The largest
upload is `MAX_UPLOAD_MB` (default 2048); large files stream to disk, not memory.

**Reading content.** Pages are static. Each query in `src/lib/content/queries.ts` is cached under a tag per
collection; the hooks in `src/payload/hooks/revalidate.ts` expire the tag on every change, so a publish
shows on the next visit without a rebuild. Queries run as an anonymous visitor, so drafts never leak.
Mappers (`src/lib/content/mappers.ts`) turn CMS documents into the shapes the components already used —
an empty field becomes a slot and a missing asset a placeholder frame, so the design holds while content
arrives.

**Roles.** `admin` manages everything including accounts; `editor` manages content and the inbox. Only
an admin can change a role, and the first account ever created is always an admin.

**Forms.** «شارك بالتوثيق» and «استمارة طلب تطوّع» post to server actions
(`src/lib/actions/submissions.ts`) that validate on the server, keep only fields the form actually has,
rate-limit per IP, trap bots with a honeypot field, and file the result — attachments included — in «الوارد».

## Content rules

- The seed (`src/payload/seed/content.ts`) holds the client-provided text, verbatim: the ten biography
  stages and their milestones («مراحل_السيرة_محايدة.md»), «من نحن», the 2016 hero quote and the contact
  email. The volunteer form and the specialities list stay in code (`src/data/volunteer.ts`): they are the
  form's structure, not editable content.
- Anything still empty in the CMS is a **slot**: it renders as a dashed `[label]` (see `Slot`,
  `ParagraphSlot`), and a missing asset renders as a `MediaFrame` tile. Interface copy and labels stay
  in `src/data/*`.
- The portrait (`public/images/character.jpg`) is uploaded by the seed and can be replaced from «الشخصية».

## Design system

- Tokens live in `src/app/(frontend)/globals.css` under `@theme`: blue `#004C60` (ground), blue scale, gold `#C99700`,
  cream `#F6F4EF`, night `#022A36`, plus the archive paper set `#EDE5D6` / `#DCD3C0` / `#C8BBA1` / `#1B1916`.
- Three bands use the paper ground instead of the blue one: «صور من الأرشيف» and «عين + المكتبة» on the
  homepage, and the whole of `/contact`. `PageHeader` takes `tone="paper"`, `MediaFrame` takes `tone="paper"`,
  and `Button` takes `variant="paper"`.
- Type rules from the guide: headings line-height 1.2, body 1.9; labels tracking 0.10em, separators 0.22em.
- Two ornament units are in use — الوردة الرباعية and النجمة الثمانية (`src/components/ui/ornaments.ts`).
  `<Ornament />` draws one, `<OrnamentGrid />` lays the 4 × 4 tile with the guide's rules (square unit,
  1×/2×/4× only, graded density via `fade`, never rotated).

## Navigation rules

`src/components/layout/TransitionLink.tsx` is the single place these live:

- **A link to another route** plays the curtain, then `router.push` — Next lands at the top of the destination.
- **A link to the page you are already on** never adds a history entry. Without a hash it glides back to the
  top; with one it glides to that section and rewrites the hash in place.
- **Browser back and forward** are untouched, so Next restores the scroll position the visitor left. `html`
  keeps `scroll-behavior: auto` for exactly this reason — every deliberate glide asks for `smooth` itself.
- **Leaving a detail page** (for example an article) uses `router.back()`, which returns the reader to their
  place in the index rather than to the top.

## Search and the assistant

Two separate things sit side by side in the navbar:

- **بحث في الموقع** (the magnifier) opens `SiteSearch`, a search over the site's own words — sections,
  the biography stages, milestones, «من نحن» and every published article, book, speech and archive title.
  It runs on the server (`src/lib/content/search.ts`, called through a server action) and normalises
  Arabic (`src/lib/arabic.ts`: diacritics, alef and ya forms, ta marbuta) so queries actually match.
- **حاور الأرشيف** opens `AssistantModal`, laid out exactly like the band under the hero. Asking from that
  band opens the same modal with the question already sent. Answers are mock records shaped like the future
  API (`src/data/chat.ts`); `ChatPanel.ask()` is the one place to swap in the real call.

## «عين» — the web

`src/components/eye/SpiderWeb.tsx`. The orb web is generated from geometry at module scope, so the server and
the client render identical paths. It breathes on its anchors while three spiders crawl. On scroll the section
pins and a scrubbed timeline runs four beats: tremble, threads snapping along their own `stroke-dashoffset`,
the sheet sagging, then the whole thing falling away with the spiders. Reduced motion gets a still web.

## «تطوّع» — the volunteer form

`src/app/(frontend)/volunteer` and `src/components/volunteer/`. The seven sections, their fields and the pledge text come
verbatim from «استمارة طلب تطوّع». «الاختصاص العلمي الدقيق» is a suggest-and-pick field
(`SpecialtyPicker.tsx`) fed by the nine categories of «لائحة الاختصاصات العلميّة والمهنيّة المطلوبة للتطوّع»;
the visitor can pick several or type one that is not on the list, as the document says the list is advisory.

## Downloads in the archive

Each archive item offers its original for download: the photograph, the uploaded video file, or the
document attached to a text. Until a file exists the control renders in its waiting state with a tooltip.
A book's «نسخة رقمية» appears as a download on the featured book.

## Motion

- `lib/gsap.ts` registers plugins once and exports `gsap`, `ScrollTrigger`, `SplitText`, `useGSAP`, `MEDIA`.
- `useReveal()` reveals `[data-reveal]` descendants with `ScrollTrigger.batch`; elements start hidden through
  CSS only when scripting is enabled, so the page still reads without JS.
- Pinned/scrubbed sections: `SpiderWeb` and `Timeline` (desktop). Each uses `gsap.matchMedia()` so mobile and
  `prefers-reduced-motion` get simpler behaviour.
- SplitText is used with `type: "lines"` only — splitting Arabic into characters breaks letter joining.
- In development only, `lib/gsap.ts` runs a watchdog that ticks GSAP manually when `requestAnimationFrame`
  is suspended (hidden tabs, embedded preview panes). It is compiled out of production builds.
